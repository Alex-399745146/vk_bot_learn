# Учебный ВК-бот — этап 2.1: Django и база

Бот, который запоминает участников. Сообщения по-прежнему приходят через
LongPoll, но теперь каждый пользователь сохраняется в SQLite, а смотреть
данные можно в Django Admin.

Этап 1 (эхо-бот без базы) остался в `main.py` — его можно запускать отдельно,
чтобы сравнивать.

---

## Структура

```
config/                 # настройки Django
  settings.py           # база, язык, время, логирование
  urls.py               # /admin/
app_tracker/            # наше приложение
  models.py             # Participant — таблица участников
  admin.py              # как участники выглядят в админке
  bot.py                # обработка сообщений + работа с базой
  lock.py               # защита от двух запущенных копий
  migrations/           # история изменений схемы БД
  management/commands/
    runbot.py           # python manage.py runbot
vk.py                   # клиент ВК: call, send_message, long_poll
main.py                 # этап 1: эхо-бот без базы
manage.py               # входная точка Django-команд
bot.log                 # лог (создаётся сам)
db.sqlite3              # база (создаётся после migrate)
```

## Как запустить

### 1. Окружение

```bash
cd C:\Users\bache\projects\vk-bot-learn
source .venv/Scripts/activate
pip install -r requirements.txt
```

### 2. Настройки

В `.env` должны быть:

```
VK_TOKEN=ключ сообщества
VK_GROUP_ID=числовой id без минуса
LOG_LEVEL=DEBUG
```

`DJANGO_DEBUG` и `DJANGO_SECRET_KEY` не обязательны локально: по умолчанию
включён режим разработки.

### 3. База

```bash
python manage.py migrate
```

Команда создаёт `db.sqlite3` и все таблицы.

### 4. Админка (по желанию)

```bash
python manage.py createsuperuser
python manage.py runserver
```

Открыть `http://127.0.0.1:8000/admin/` → раздел **Участники**.

### 5. Бот

```bash
python manage.py runbot
```

Теперь напиши сообществу в «Сообщения» (не на стену) любой текст.

- Первый раз: `Привет, Александр! Я записал тебя в базу…`
- Повторно: `С возвращением, Александр! Ты в базе с 13.11.2026.`

Остановка — `Ctrl+C`.

## Что произошло с данными

При первом сообщении выполнился код:

```python
participant, created = Participant.objects.get_or_create(
    vk_id=vk_id,
    defaults={"name": name},
)
```

- `Participant` — Python-класс, он же таблица в базе;
- `objects` — менеджер запросов;
- `get_or_create` — «найди или создай»: ищет по `vk_id`, а если не нашёл,
  создаёт запись с именем.

После перезапуска бот снова находит запись по `vk_id`, поэтому помнит человека.

Проверить из консоли:

```bash
python manage.py shell
```

```python
from app_tracker.models import Participant
Participant.objects.all()
```

## Как это работает

```
runbot.py              vk.py                         ВКонтакте
    |                    |                               |
    |-- vk.long_poll() ->|                               |
    |                    |-- groups.getLongPollServer -->|
    |                    |<-- server, key, ts -----------|
    |                    |-- GET a_check (ждёт 25 сек) ->|
    |                    |<-- updates -------------------|
    |<-- update ---------|                               |
    |                                                      |
    |-- bot.handle_update()                                |
    |     |-- Participant.objects.get_or_create()          |
    |     |-- vk.send_message() -------------------------->|
```

`ts` — номер последнего прочитанного события. Мы передаём его в следующий
запрос, чтобы ВК не присылал одно и то же дважды.

## Что делает каждая часть

### `vk.py`

| Функция | Зачем |
|---|---|
| `VK.call` | один вызов любого метода ВК; ошибка ВК → `RuntimeError` |
| `VK.send_message` | отправляет текст, добавляет `random_id` |
| `VK.long_poll` | бесконечный поток событий и переподключение |
| `VK._long_poll_session` | получает `server`, `key`, `ts` |

### `app_tracker`

| Что | Зачем |
|---|---|
| `models.py` | описывает таблицу `Participant` |
| `admin.py` | показывает таблицу в браузере |
| `bot.py` | решает, что делать с сообщением |
| `lock.py` | не даёт запустить две копии |
| `management/commands/runbot.py` | связывает Django и LongPoll |

### Django-термины

- **Модель** — класс, описывающий таблицу (`Participant`).
- **Миграция** — файл с инструкцией, как изменить схему БД.
- **ORM** — способ работать с базой без SQL: `Participant.objects.all()`.
- **Админка** — готовый веб-интерфейс к моделям.

## Почему ошибки проверяются, но просто

ВК при ошибке отвечает HTTP 200 и кладёт её внутрь JSON:

```json
{"error": {"error_code": 100, "error_msg": "..."}}
```

Если не проверить `error`, метод молча вернёт `None`, и бот будет делать вид,
что всё отправилось. Поэтому проверка нужна, но пока достаточно двух строк и
обычного `RuntimeError`. Свой класс с кодом ошибки и повторами добавим позже.

## Почему `random_id`

ВК считает сообщения дублями, если у них одинаковые `peer_id` + `random_id`.
Мы генерируем случайное число на каждое сообщение.

## Почему два одинаковых ответа

Если запустить две копии, обе получат одно событие и обе ответят. Поэтому
`lock.py` занимает локальный порт: второй запуск завершается с сообщением
«Бот уже запущен в другом окне».
