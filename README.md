# Учебный ВК-бот — этап 2.4: цели на месяц и одна отметка в день

Три цели ставятся на месяц. День считается выполненным, если сделаны все три.
После завершения отметки кнопка «Отметиться» исчезает до следующих суток —
то есть до 00:00 по Москве.

---

## Что уже работает

- LongPoll: получение сообщений;
- SQLite: участники, цели, состояния, отметки;
- меню с кнопками;
- онбординг: три цели на месяц → подтверждение;
- «Отметиться»: три вопроса Да/Нет → запись за сегодня;
- кнопка «Отметиться» скрыта, пока есть отметка за сегодня;
- повторная отметка через «Изменить»;
- админка: участники, состояния, отметки.

Этап 1 (эхо-бот) остался в `main.py` — для сравнения.

## Как проверить

1. Напиши `привет`.
2. Бот попросит три цели по очереди. Например:
   - `активность 15 минут`
   - `зарядка после сна`
   - `без сахара в кофе`
3. Покажет рецепт и кнопки `[Верно] [Изменить]`.
4. Нажми «Верно» — появится меню:

```
[Отметиться] [Мои цели]
[Изменить цели]
```

5. «Отметиться» → три вопроса «Выполнено?» с кнопками `[Да] [Нет]`.
6. После третьего ответа бот запишет отметку и покажет:

```
Записал: 2 из 3.
1. ✅ активность 15 минут
2. ❌ зарядка после сна
3. ✅ без сахара в кофе
```

7. Нажми «Отметиться» ещё раз — кнопки уже нет. В меню будет написано
   «Сегодня уже отмечено: 2 из 3. Новая отметка будет доступна завтра».
8. Перезапусти бота: цели и сегодняшняя отметка останутся на месте.
9. На следующий день после 00:00 отметка снова появится, потому что запись
   за новую дату ещё не создана.

## Как устроено

### Состояния

```
IDLE → ONBOARD_GOAL → ONBOARD_CONFIRM → IDLE
IDLE → REPORTING (три вопроса) → IDLE
```

- `ONBOARD_GOAL` — ждём текст очередной цели. Номер цели и уже введённые
  цели лежат в `BotState.data`: `{"goals": ["...", "..."]}`;
- `ONBOARD_CONFIRM` — ждём «Верно» или «Изменить»;
- `REPORTING` — ждём ответы Да/Нет. В данных:
  `{"index": 1, "results": [true]}`.

Одно состояние на весь цикл, а не три отдельных: номер шага хранится в
`data["index"]`. Так код короче и не нужно плодить состояния.

### Модели

**Participant** — человек и его цели на месяц:

```python
goal_1, goal_2, goal_3
goals_month   # "2026-11"
```

Свойства:

```python
participant.goals       # [goal_1, goal_2, goal_3]
participant.has_goals   # цели заполнены И поставлены на текущий месяц
```

`has_goals` сравнивает `goals_month` с текущим месяцем. Поэтому 1-го числа
цели «сгорают» и бот просит поставить новые.

**Report** — отметка за день:

```python
date
goal_1_done, goal_2_done, goal_3_done
```

Свойства:

```python
report.goals_done   # сколько выполнено, 0..3
report.completed    # все три
```

Уникальность `(participant, date)` гарантирует одна запись на день. Повторная
отметка обновляет её через `update_or_create`.

**BotState** — где человек в диалоге:

```python
state = "REPORTING"
data = {"index": 1, "results": [true]}
```

### Почему «Отметиться» исчезает

`Report` уникален по паре `(participant, date)`. Значит, на один день — одна
отметка. Меню собирается функцией `main_menu(can_checkin=...)`:

```python
report = today_report(participant)
keyboard = keyboards.main_menu(can_checkin=report is None)
```

`today_report` берёт `timezone.localdate()` — дату по часовому поясу из
`settings.TIME_ZONE` (`Europe/Moscow`). В полночь дата меняется, запись за
новый день не находится, и кнопка возвращается. Отдельный cron для этого не
нужен: клавиатура пересобирается при каждом сообщении.

Старая кнопка могла остаться в чате. Если её нажать, бот увидит существующую
отметку и покажет статус с `[Изменить] [Меню]` — новая клавиатура уже будет
без «Отметиться».

### Кнопки

Reply-кнопка присылает текст и `payload`:

```json
{"cmd": "menu:checkin"}
```

`bot.py` сначала проверяет `payload`, потом текст. Команды:

| cmd | Действие |
|---|---|
| `menu:checkin` | начать отметку |
| `menu:goals` | показать рецепт |
| `menu:edit` | изменить цели |
| `menu:cancel` | сброс и меню |
| `onb:ok` / `onb:edit` | подтвердить / изменить цели |
| `rep:yes` / `rep:no` | ответ по цели |
| `rep:edit` | переотметить день |
