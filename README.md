# Учебный ВК-бот — этап 2.2: меню и онбординг

Бот запоминает участников и ведёт их по шагам: привычка → отказ →
подтверждение → меню. Состояние диалога хранится в базе, поэтому перезапуск
бота не сбрасывает сценарий.

---

## Что уже работает

- LongPoll: бот получает сообщения;
- SQLite: участники и состояния диалога сохраняются;
- reply-меню с кнопками;
- онбординг из трёх шагов;
- «Мои правила» и «Изменить правила»;
- админка: участники и состояния.

Этап 1 (эхо-бот) остался в `main.py` — можно сравнивать.

## Как проверить

1. Напиши боту `привет` (или `/start`).
2. Он попросит привычку — напиши, например `зарядка 10 минут`.
3. Попросит отказ — напиши `сахар`.
4. Покажет проверку и кнопки `[Верно] [Изменить]`.
5. Нажми «Верно» — появится меню:

```
[Мои правила] [Изменить правила]
```

6. «Мои правила» — покажет сохранённые правила.
7. «Изменить правила» — запустит онбординг заново.

Проверь перезапуск: останови бота (`Ctrl+C`) и запусти снова. Напиши
`/start` — правила на месте, состояние диалога тоже.

## Как устроен диалог

Состояния в `app_tracker/states.py`:

```
IDLE → ONBOARD_HABIT → ONBOARD_REFUSAL → ONBOARD_CONFIRM → IDLE
```

- `IDLE` — ждём кнопку меню;
- `ONBOARD_HABIT` — ждём текст привычки;
- `ONBOARD_REFUSAL` — ждём текст отказа;
- `ONBOARD_CONFIRM` — ждём «Верно» или «Изменить».

Текущее состояние и черновик ответов лежат в `BotState`:

```python
state.state = "ONBOARD_REFUSAL"
state.data = {"habit": "зарядка 10 минут"}
```

Когда человек нажимает «Верно», черновик переносится в `Participant`:

```python
participant.habit = data["habit"]
participant.refusal = data["refusal"]
participant.save()
```

## Почему это переживает перезапуск

В этапе 1 счётчик жил в переменной и обнулялся. Здесь состояние — строка в
таблице `BotState`. Новый процесс читает её и продолжает с того же шага.

## Кнопки и payload

Кнопка reply-клавиатуры отправляет обычное сообщение, но с полем `payload`:

```json
{"cmd": "menu:edit"}
```

`bot.py` сначала проверяет `payload_command(message)`, и только потом смотрит
на текст. Поэтому кнопки работают даже если человек ничего не напечатал.

## Клавиатуры

`keyboards.py` собирает JSON для ВК:

- `main_menu()` — «Мои правила» и «Изменить правила»;
- `confirm_keyboard()` — «Верно» и «Изменить»;
- `empty_keyboard()` — убирает клавиатуру, пока ждём текст.

Пустая клавиатура нужна потому, что ВК сам не скрывает старые кнопки.

## Файлы и функции

| Файл | Что делает |
|---|---|
| `vk.py` | HTTP-клиент и LongPoll |
| `bot.py` | маршрутизация: команда → состояние → ответ |
| `states.py` | константы состояний |
| `keyboards.py` | JSON reply-клавиатур |

| `admin.py` | просмотр данных в браузере |
| `runbot.py` | запуск цикла LongPoll внутри Django |

### `bot.py`

| Функция | Зачем |
|---|---|
| `handle_update` | входная точка: разбирает событие |
| `handle_text` | текст в зависимости от состояния |
| `handle_command` | нажатия кнопок по `payload` |
| `begin_onboarding` | начинает или перезапускает онбординг |
| `show_menu` | показывает правила и меню |
| `set_state` | записывает состояние в базу |
| `payload_command` | достаёт `cmd` из payload |
