# Учебный ВК-бот — периоды 3–28 и окно целей 28–3

Три цели ставятся на период — с 3-го по 28-е число. День считается
выполненным, если сделаны все три. После этого кнопка «Отметиться» исчезает
до следующих суток — до 00:00 по Москве. Если выполнены не все цели, кнопка
остаётся, чтобы можно было дополнить отметку.

Цели на новый период ставятся в окне с 28-го прошлого месяца по 3-е текущего.

---

## Что уже работает

- LongPoll: получение сообщений;
- SQLite: участники, цели, состояния, отметки;
- меню с кнопками;
- «Мои цели»: цели периода, баллы, остаток Chill и VK ID для регистрации;
- веб-кабинет: карточка участника с фото из ВК (или картинкой по умолчанию) и значком пола;
- рабочий период 3–28, окно целей 28–3, перерыв между периодами;
- онбординг: три цели на период → подтверждение;
- «Отметиться»: три вопроса Да/Нет → запись за сегодня;
- «Chill 3/3»: до 3 раз за период, предупреждение, закрывает день;
- «⏸ Пауза 3/3»: до 3 раз в году, пропускает следующий период с 0 баллов;
- кнопка «Отметиться» скрыта только когда выполнены все три цели;
- повторная отметка через «Изменить» или повторное «Отметиться»;
- админка: участники, состояния, отметки.

История этапа 1 (эхо-бот без базы) осталась в git — в текущей версии его нет.

### Что в админке

| Раздел | Адрес | Что там |
|---|---|---|
| Участники | `/admin/app_tracker/participant/` | VK ID, имя, цели, месяц |
| Отметки | `/admin/app_tracker/report/` | 3 из 3, Chill, фильтры по датам |
| Профили | `/admin/app_users/profile/` | связь веб-аккаунта с участником |
| Состояния диалогов | `/admin/app_tracker/botstate/` | текущий шаг диалога, скрыто из меню |

**«Состояния диалогов» намеренно не показывается** в списке приложения на
главной странице админки. Это техническая таблица для отладки, а не данные
для ежедневной работы, поэтому её убрали из меню через `get_model_perms`.
Открыть её можно только по прямой ссылке:

```
http://127.0.0.1:8000/admin/app_tracker/botstate/
```

В строке лежит `state` (например, `REPORTING`), `data` (черновик ответов) и
`updated_at`. Одна строка на человека, она перезаписывается на каждом шаге
и сбрасывается в `IDLE`. Это **не история ввода**, а текущее положение в
диалоге: без неё бот не смог бы вести онбординг, отметку и Chill по шагам.

### Как связать аккаунт с ботом

Бот знает человека по `vk_id`. При регистрации нужно указать тот же VK ID:

1. сначала напиши боту `/start`, чтобы появился `Participant`;
2. открой `/register/`, задай логин, пароль и VK ID;
3. создастся `User` и `Profile`, связанный с этим `Participant`;
4. на `/` появятся цели, сегодняшняя отметка и последние результаты.

Если VK ID не найден или уже привязан к другому аккаунту, форма покажет ошибку.

> Это учебный проект для доверенной группы: владение VK ID не проверяется
> через ВК. Для публичного запуска понадобится подтверждение через VK OAuth.

## Как проверить

1. Напиши `привет`.
2. Бот попросит три цели по очереди. Например:
   - `активность 15 минут`
   - `зарядка после сна`
   - `без сахара в кофе`
3. Покажет рецепт и кнопки `[Верно] [Изменить]`.
4. Нажми «Верно» — появится меню:

```
[Отметиться] [Chill 3/3]
[Мои цели] [Изменить цели]
```

5. «Отметиться» → три вопроса «Выполнено?» с кнопками `[Да] [Нет]`.
   «Chill» → предупреждение `[Передумал] [Продолжить]`; после подтверждения
   день закрыт до завтра, а счётчик Chill уменьшается.
6. После третьего ответа бот запишет отметку и покажет:

```
Записал: 2 из 3.
1. ✅ активность 15 минут
2. ❌ зарядка после сна
3. ✅ без сахара в кофе
```

7. Если выполнены не все три (например, 2 из 3), кнопка «Отметиться»
   остаётся — можно нажать и дополнить отметку.
8. Когда все три выполнены, кнопки «Отметиться» больше нет, а в меню написано
   «Сегодня все три цели выполнены. Новая отметка будет доступна завтра».
9. На следующий день после 00:00 кнопка снова появится: записи за новую дату
   ещё нет.

## Как устроено

### Состояния

```
IDLE → ONBOARD_GOAL → ONBOARD_CONFIRM → IDLE
IDLE → REPORTING (три вопроса) → IDLE
```

- `ONBOARD_GOAL` — ждём текст очередной цели. Номер цели и уже введённые
  цели лежат в `BotState.data`: `{"goals": ["...", "..."]}`;
- `ONBOARD_CONFIRM` — ждём «Верно» или «Изменить»;
- `REPORTING` — ждём ответы Да/Нет. В данных:
  `{"index": 1, "results": [true]}`.

Одно состояние на весь цикл, а не три отдельных: номер шага хранится в
`data["index"]`. Так код короче и не нужно плодить состояния.

### Модели

**Participant** — человек и его активные цели:

```python
goal_1, goal_2, goal_3
goals_month   # "2026-11" — рабочий период, в котором цели активны
```

Свойства:

```python
participant.goals       # [goal_1, goal_2, goal_3]
participant.has_goals   # цели заполнены И идёт рабочий период
```

`has_goals` проверяет, что цели относятся к текущему рабочему периоду
(`work_month()`): с 3-го по 28-е. В перерыве 29–2 он всегда `False`.

**GoalPeriod** — цели на конкретный период:

```python
participant FK
month        # "2026-12"
goal_1..3
status       # active | paused
paused_at    # когда взята пауза, для лимита 3 в год
```

Уникальность `(participant, month)`. Пока период не начался, цели лежат
только здесь; 3-го числа `sync_period_goals()` переносит их в `Participant`.
Если статус `paused`, цели очищаются, отметки и баллы недоступны.

**Report** — отметка за день:

```python
date
goal_1_done, goal_2_done, goal_3_done
is_chill
```

Свойства:

```python
report.goals_done   # сколько выполнено, 0..3
report.completed    # все три
```

Уникальность `(participant, date)` гарантирует одна запись на день. Повторная
отметка обновляет её через `update_or_create`.

**BotState** — где человек в диалоге:

```python
state = "REPORTING"
data = {"index": 1, "results": [true]}
```

### Периоды и пауза

| Даты | Что происходит |
|---|---|
| 28–31 прошлого месяца | рабочий период прошёл, окно целей открыто |
| 1–2 | перерыв, окно целей открыто |
| 3 | старт рабочего периода; последний день окна целей |
| 3–28 | отметки, баллы, Chill |
| 29–2 | перерыв; дальше новый цикл |

Константы:

```python
ON_PERIOD_GOALS_START = 28
ON_PERIOD_GOALS_END = 3
ON_PERIOD_WORK_START = 3
ON_PERIOD_WORK_END = 28
LIMIT_PAUSE = 3
```

Правила:

- меню строится в три этажа: `[Отметиться] [Chill]`, затем
  `[Изменить цели] [Пауза]`, затем `[Мои цели] [Инструкция]`;
- Chill не показывается без «Отметиться», пауза — без «Изменить цели»;
- «Изменить цели» видна только 28–3 и зелёная; вне окна `menu:edit` отвечает
  «Окно целей закрыто»;
- «Отметиться» и Chill — только 3–28 и только при поставленных целях;
- постановка целей = автоматическое участие в сезоне;
- если к 4-му цели не поставлены, период пропущен — ждать 28-го;
- баллы считаются по диапазону 3–28, а не по календарному месяцу;
- на 3-е и 28-е периоды пересекаются: доступны обе кнопки.

Пауза:

- кнопка `⏸ Пауза 3/3` красная, видна только в окне 28–3;
- предупреждение `[Назад] [Продолжить]`;
- до `LIMIT_PAUSE` раз за календарный год, считается по `paused_at`;
- пропускает следующий период: `GoalPeriod(status="paused")`, баллы 0;
- после 3 пауз кнопка исчезает до января;
- если период уже в паузе, повторно она не берётся.

### Почему «Отметиться» исчезает

`Report` уникален по паре `(participant, date)`. Значит, на один день — одна
отметка. Меню собирается функцией `main_menu(can_checkin=..., chill_left=...)`:

```python
report = today_report(participant)
used = chill_count(participant)
can_checkin = report is None or (not report.completed and not report.is_chill)
can_chill = report is None and used < CHILL_LIMIT
keyboard = keyboards.main_menu(can_checkin=can_checkin, chill_left=...)
```

`completed` — это `report.goals_done == 3`. Поэтому при 2 из 3 кнопка остаётся:
человек может нажать её и дополнить день. При 3 из 3 кнопка скрывается, пока
не наступит новый день.

`today_report` берёт `timezone.localdate()` — дату по часовому поясу из
`settings.TIME_ZONE` (`Europe/Moscow`). В полночь дата меняется, запись за
новый день не находится, и кнопка возвращается. Отдельный cron для этого не
нужен: клавиатура пересобирается при каждом сообщении.

Старая кнопка могла остаться в чате. Если её нажать после выполнения всех
трёх целей, бот покажет статус с `[Изменить] [Меню]` — новая клавиатура уже
будет без «Отметиться».

### Chill

Chill — это день отдыха по выбору участника: 0 баллов, но день закрыт.

- `CHILL_LIMIT = 3` в `app_tracker/bot/constants.py`;
- поле `Report.is_chill`, миграция `0006_report_is_chill`;
- кнопка `❄️ Chill 3/3` показывает **остаток**: `CHILL_LIMIT - used`;
- при нажатии — предупреждение `[Передумал] [Продолжить]`;
- после подтверждения создаётся `Report(is_chill=True)` с тремя `False`;
- `Отметиться` и `Chill` скрываются до следующих суток;
- Chill не сочетается с обычной отметкой: если за сегодня уже есть `Report`
  (в том числе частичный 1/3), Chill не предлагается — один день, один статус;
- после третьего Chill за период кнопка исчезает, а на старую кнопку бот
  отвечает «Лимит Chill исчерпан»;
- `period_points()` не считает Chill: `is_chill=False` в фильтре.

Счётчик сбрасывается сам в начале периода: `chill_count()` фильтрует по
диапазону 3–28 текущего периода, отдельного cron нет.

### Кнопки

Reply-кнопка присылает текст и `payload`:

```json
{"cmd": "menu:checkin"}
```

`bot.py` сначала проверяет `payload`, потом текст. Команды:

| cmd | Действие |
|---|---|
| `menu:checkin` | начать отметку |
| `menu:goals` | показать рецепт |
| `menu:edit` | изменить цели |
| `menu:cancel` | сброс и меню |
| `menu:help` | инструкция и меню |
| `chill:start` / `chill:ok` | показать предупреждение / записать Chill |
| `pause:start` / `pause:ok` | показать предупреждение / взять паузу |
| `pause:cancel` | отменить паузу |
| `onb:ok` / `onb:edit` | подтвердить / изменить цели |
| `onb:back` | шаг назад: к предыдущей цели или в меню |
| `rep:yes` / `rep:no` | ответ по цели |
| `rep:edit` | переотметить день |

Текстовые команды:

- `/start` — меню или старт онбординга;
- `/help` (или «помощь») — эта справка.
