## 1. Git: как работаем

### 1.1 Схема веток

```
main        — стабильная версия, только релизы
develop     — интеграция, сюда вливаются все фичи
feature/*   — короткие ветки под конкретные задачи
```

Ветки создаются **от `develop`**, а не «одна ветка на человека».

Личные долгоживущие ветки не используем: они расходятся, копят конфликты и мешают понять, что готово к слиянию.

### 1.2 Если второй разработчик — коллаборатор (рекомендуется)

В GitHub: **Settings → Collaborators → Add people**, доступ **Write**.

Он работает в том же репозитории:

```bash
git clone https://github.com/ВАШ_ЛОГИН/vk-bot-learn.git
cd vk-bot-learn

git switch develop
git pull --rebase origin develop

git switch -c feature/chill
# работа, коммиты

git push -u origin feature/chill
```

Дальше на GitHub: **Compare & pull request** → база `develop` → ревью → merge.

После merge:

```bash
git switch develop
git pull --rebase origin develop
git branch -d feature/chill
```

### 1.3 Если коллаборатора добавить нельзя

Тогда второй разработчик делает **fork** репозитория:

```bash
git clone https://github.com/ЕГО_ЛОГИН/vk-bot-learn.git
cd vk-bot-learn
git remote add upstream https://github.com/ВАШ_ЛОГИН/vk-bot-learn.git
git fetch upstream
git switch -c feature/chill upstream/develop
git push -u origin feature/chill
```

И открывает PR из форка в ваш `develop`.

**Форк — это не ветка, а отдельная копия репозитория.**

### 1.4 «Закрепить ветку за человеком»

Git не умеет закреплять ветки. В GitHub для этого есть:

- **Branch protection** для `main` и `develop`:
  - запрет прямых пушей;
  - обязательный PR;
  - минимум 1 approval;
  - запрет force push.
- **CODEOWNERS** — автоматически назначает ревьюера на файлы:

```gitignore
# .github/CODEOWNERS
/app_tracker/bot/       @логин_A
/app_tracker/models.py  @логин_B
/app_users/             @логин_B
```

- **Assignees / Reviewers** в PR — это и есть закрепление задачи за человеком.

### 1.5 Первый push

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/vk-bot-learn.git
git push -u origin main develop
```

Сейчас `main` — старая база, `develop` — актуальная версия. Когда `develop` станет стабильным, влить его в `main`.

### 1.6 Ежедневный цикл

```bash
git switch develop
git pull --rebase origin develop

git switch feature/название
git rebase develop
```

Конфликты решаются в своей ветке через rebase, а не merge из `develop` в фичу.

### Главные правила

1. **`models.py` и миграции меняет только B.**
2. A не делает `makemigrations`.
3. Если A нужна новая функция в `storage.py`, B добавляет её по согласованному имени.
4. Перед изменением модели B пишет в чат: «беру models.py, миграция X», делает, коммитит, пушит.
5. A перед продолжением делает `git pull --rebase`.

### 4.1 Модераторы

- Django-группа `Модераторы`.
- Права:
  - `view_*` на `participant`, `report`, `media`, `activity`, `goalperiod`;
  - `change_*` на те же модели — модераторы должны исправлять данные;
  - `delete` не давать.
- Пользователям группы выставить `is_staff = True`, иначе админка недоступна.
- Добавить модель `ModeratorNote`:
  ```python
  ModeratorNote:
      participant FK
      author      FK(User)
      text        TextField
      created_at
  ```
  Модератор пишет замечание в админке; участник видит его в своём кабинете
  (только чтение). Другие участники замечаний не видят.
- Создание группы — data-миграцией.

**Готово, когда:** модератор входит в `/admin/`, видит и правит данные,
пишет замечания, но не удаляет записи; участник видит замечания у себя.

- `Participant.sex = SmallIntegerField(choices=[(0, "—"), (1, "Ж"), (2, "М")], default=0)`.

**Перед миграцией:** B предупреждает A, A делает `git pull --rebase`.

### 4.3 Chill

- Константа `CHILL_LIMIT = 3` в `app_tracker/bot/constants.py`.
- `Report.is_chill = BooleanField(default=False)`.
- Кнопка в меню: `[Отметиться] [Chill 3/3]`.
- Использовано за месяц:
  ```python
  Report.objects.filter(
      participant=participant,
      date__year=day.year,
      date__month=day.month,
      is_chill=True,
  ).count()
  ```
- «3/3» — остаток: `CHILL_LIMIT - used`.
- При нажатии: предупреждение «Chill можно 3 раза в месяц. Это 1-й. Продолжить?»
  Кнопки `[Передумал]` (зелёная) и `[Продолжить]` (красная).
- После лимита кнопку не показывать; на старую кнопку отвечать «Лимит исчерпан».
- **Chill закрывает «Отметиться» до завтра.** После Chill за сегодня
  `Отметиться` не показывается, как и после полной отметки 3/3.
- **Chill не сочетается с частичной отметкой.** Если за сегодня уже есть
  отчёт (например, 1/3), Chill не предлагается: сначала нужно завершить
  или изменить текущую отметку. Один день — один статус.
- Цвета ВК: `primary` — синий, `secondary` — серый, `positive` — зелёный,
  `negative` — красный. **Жёлтого и оранжевого в ВК нет.**

**Готово, когда:** кнопка показывает остаток, считает Chill за месяц,
скрывается после 3-го, предупреждение работает, после Chill `Отметиться`
скрыта до следующих суток.

### 4.4 «Изменить цели» и пауза

> **Решение 17.11.2026.** Рабочий период — **3–28**, окно целей — **28–3**
> (оба включительно, 3-е и 28-е — переходные дни).
> Константы: `ON_PERIOD_GOALS_START = 28`, `ON_PERIOD_GOALS_END = 3`,
> `ON_PERIOD_WORK_START = 3`, `ON_PERIOD_WORK_END = 28`,
> `LIMIT_PAUSE = 3`.
> Пауза доступна только в окне и пропускает следующий период; лимит
> считается по календарному году через `GoalPeriod.paused_at`.
> Формулировки ниже про «29» и «месяц» устарели.

Самая сложная фича: текущая модель хранит только один набор целей на участника.

Нужна новая модель:

```python
GoalPeriod:
    participant FK
    month         # "2026-11"
    goal_1..3
    status        # active | paused
    unique(participant, month)
```

Почему:

- 29 ноября ставим цели на декабрь, ноябрьские продолжают работать;
- 1 декабря декабрьские становятся текущими;
- пауза — это `GoalPeriod(month=декабрь, status=paused)`.

Константы:

```python
ON_PERIOD_GOALS = 29
OFF_PERIOD_GOALS = 3    # включительно
PAUSE_LIMIT = 3         # за календарный год
```

Функции:

- `is_goals_window(day)` — `day >= 29 or day <= 3`;
- `target_goals_month(day)` — если `day >= 29`, следующий месяц, иначе текущий;
- кнопка «Изменить цели» видна только в окне;
- паузы считаются по `GoalPeriod` со статусом `paused` за текущий календарный год;
- подпись `Остывать 3/3` — остаток до `PAUSE_LIMIT`.

**Окно 29–3 работает для всех месяцев, включая текущий.**
В окне ставим цели на следующий месяц; текущий месяц продолжает работать
до конца.

Состояния кнопки «Остывать»:

| Ситуация | Кнопка | Поведение |
|---|---|---|
| Пауз за год меньше 3, в этом окне пауза ещё не выбрана | активна, `Остывать 2/3` | выбор паузы |
| Пауза уже выбрана в текущем окне | видна, но неактивна, тёмно-серая (`secondary`), `Остывать (с 29)` | нажатие → «Кнопка активируется 29 числа» |
| За год использовано 3 паузы | скрыта | на старую кнопку → «Лимит пауз исчерпан» |
| Наступило 29-е | снова активна, если лимит не исчерпан | выбор паузы |

Важно: в ВК нет настоящего disabled-состояния. «Неактивная» кнопка —
это `secondary`-цвет и обработчик, который отвечает текстом и ничего не меняет.

После выбора «Остывать месяц» создаётся
`GoalPeriod(month=target, status=paused)`. Это **пропуск месяца**: цели на
этот месяц не задаются. Повторно в том же окне пауза не создаётся.
Если в том же окне человек снова открывает «Изменить цели»,
кнопка паузы уже неактивна, но кнопка «Цели прогрева» работает.
За календарный год можно пропустить не более 3 месяцев.

Старые `Participant.goal_1..3/goals_month` перенести в `GoalPeriod` data-миграцией.

**Это отдельная ветка `feature/goals-window`.**

**Готово, когда:** кнопка появляется 29–3, «Остывать» становится неактивной
после использования и снова активной 29-го, после 3 пауз за год скрывается,
цели ставятся на следующий месяц.

### 4.5 «Я перегорел»

- Кнопка в меню.
- Экран предупреждения: «Это удалит твои данные и завершит участие».
  Кнопки `[Передумал]` (зелёная) и `[Продолжить]` (красная).
- После подтверждения:
  - удалить `Participant`, `GoalPeriod`, `Report`, `Media`, `Activity`, `Profile`, `BotState`;
  - **удалить веб-аккаунт `User`**;
  - удалить файлы медиа с диска;
  - уведомить Влада через `OWNER_VK_ID` (кто именно удалился);
  - отправить деловое сообщение: «Данные удалены. Пожалуйста, покинь сообщество самостоятельно».
- **Бот не может гарантированно удалить человека из сообщества** токеном сообщества.
  Это делается вручную или отдельным методом с пользовательским токеном.
  Не обещать автоматическое исключение.

**Готово, когда:** подтверждение работает, данные, файлы и веб-аккаунт
удаляются, Влад получает уведомление.

### 4.6 Отметка с медиа

- Добавить в `Report`:
  - `goal_1_note`, `goal_2_note`, `goal_3_note` (`TextField`, blank) —
    короткое пояснение, если по цели нет медиа;
  - либо один `note`, если решим хранить пояснение на весь день.
    **Рекомендация:** три поля, потому что пояснение относится к конкретной цели.
- Модель `Media`:
  ```python
  report FK (nullable)
  activity FK (nullable)
  goal_index SmallInteger (1..3, nullable)
  kind photo/video
  file
  external_id
  source_url
  duration
  created_at
  ```
  Ровно один владелец: либо `report`, либо `activity`.
- Константы:
  ```python
  MEDIA_PER_GOAL = 3
  MEDIA_PER_ACTIVITY = 1
  VIDEO_MAX_SECONDS = 60
  ```
- Поток отметки:
  1. сначала задаются все три вопроса «Да/Нет»;
  2. после опроса бот идёт по целям, где ответ «Да»:
     - предлагает медиа для этой цели (до 3 файлов);
     - если медиа нет — просит короткое пояснение по этой цели;
     - если медиа есть — пояснение опционально;
  3. для целей с ответом «Нет» медиа и пояснение не запрашиваются;
  4. после обхода всех выполненных целей — сохранение `Report` и всех `Media`.
- Видео — **до 60 секунд**, короче можно.
- Фото скачивать. Видео — best-effort; если файл не скачался,
  сохранять `external_id` и `source_url` (хотя бы ссылку/вложение ВК).
- Файлы в `MEDIA_ROOT/reports/<YYYY-MM>/<report_id>/`.
- Команда `cleanup_media` — удалять всё старше двух месяцев
  (текущий и прошлый месяц оставляем).
- «Отметиться» — красная (`negative`). «Отмена» — жёлтой в ВК нет,
  использовать `primary` (синий) или `secondary`.

**Готово, когда:** по каждой выполненной цели можно приложить до 3 файлов
или пояснение, медиа и текст сохраняются, видео-ссылка не теряется,
старые файлы удаляются по cron.

### 4.7 Активность

- Модель `Activity`:
  ```python
  participant FK
  kind: self_day | boost | meeting
  note
  points = 2
  created_at
  ```
- Константа `ACTIVITY_POINTS = 2`; поле `points` сохраняет значение на момент
  создания, чтобы старые записи не менялись при смене константы.
- Баллы идут в общую статистику месяца и дашборд.
- Меню `[Активность]`; оранжевого в ВК нет — использовать `positive` или `primary`.
- 4 кнопки: «Мой день», «Буст», «Встреча», «Отмена».
- После выбора — медиа/пояснение по тем же правилам, что в отметке,
  но **максимум 1 файл на активность**.
- Лимит: **только выходные, не более 4 активностей в месяц суммарно**
  (`ACTIVITY_LIMIT = 4`). При исчерпании кнопки активностей не показываются;
  на старую кнопку — сообщение о лимите.

**Готово, когда:** все 4 кнопки работают, активность сохраняется с 2 баллами,
медиа/пояснение пишутся, баллы видны в статистике.

## 5. Правила работы

1. Никто не пушит напрямую в `develop` — только PR.
2. Одна фича — одна ветка:
   - `feature/chill-limit`
   - `feature/goals-window`
   - `feature/media-checkin`
   - `feature/activity`
   - `feature/burnout`
   - `feature/moderation`
   - `feature/profile-photo`
3. Перед началом дня:
   ```bash
   git switch develop
   git pull --rebase origin develop
   git switch feature/...
   git rebase develop
   ```
4. Миграции — только B.
5. PR — маленький, до 300–400 строк, с описанием «что сделано, как проверить».
6. Ревью — второй разработчик смотрит код и прогоняет сценарий вручную.
7. Конфликты — через `git rebase develop` в своей ветке.
8. Не редактировать применённые миграции. Только новая миграция.
9. `.env`, `db.sqlite3`, `bot.log` не коммитить.
10. После merge удалить ветку и обновить `develop`.

2. **«Остывать»** — это пропуск месяца. После использования в текущем окне
   кнопка остаётся видимой, но неактивна (тёмно-серая, `secondary`) до 29-го.
   Нажатие показывает «Кнопка активируется 29 числа». После 3 пропусков за год
   кнопка скрывается. На 29-е снова активна, если лимит не исчерпан.
3. **Окно 29–3** работает для всех месяцев, включая текущий. В окне ставим
   цели на следующий месяц, текущий продолжает работать.
4. **Активности:** только выходные, не более **4 в месяц суммарно**.
   Каждая даёт **2 балла**: `ACTIVITY_POINTS = 2`.
5. **Медиа:** до 3 файлов на каждую цель, 1 файл на активность.
   Сначала все три вопроса, потом медиа/пояснения по целям с ответом «Да».
   Видео — до 60 секунд. Если видео не скачалось — сохранять `external_id`
   и ссылку/вложение ВК.
6. **«Перегорел»:** удалять и веб-аккаунт `User`, уведомлять администратора.
7. **Модераторы:** могут изменять данные и писать замечания
   (`ModeratorNote`), удалять — нет. **Участник видит замечания в кабинете.**
