## 1. Git: как работаем

### 1.1 Схема веток

```
main        — стабильная версия, только релизы
develop     — интеграция, сюда вливаются все фичи
feature/*   — короткие ветки под конкретные задачи
```

Ветки создаются **от `develop`**, а не «одна ветка на человека».

Личные долгоживущие ветки не используем: они расходятся, копят конфликты и мешают понять, что готово к слиянию.

### 1.2 Если второй разработчик — коллаборатор (рекомендуется)

В GitHub: **Settings → Collaborators → Add people**, доступ **Write**.

Он работает в том же репозитории:

```bash
git clone https://github.com/ВАШ_ЛОГИН/vk-bot-learn.git
cd vk-bot-learn

git switch develop
git pull --rebase origin develop

git switch -c feature/chill
# работа, коммиты

git push -u origin feature/chill
```

Дальше на GitHub: **Compare & pull request** → база `develop` → ревью → merge.

После merge:

```bash
git switch develop
git pull --rebase origin develop
git branch -d feature/chill
```

### 1.3 Если коллаборатора добавить нельзя

Тогда второй разработчик делает **fork** репозитория:

```bash
git clone https://github.com/ЕГО_ЛОГИН/vk-bot-learn.git
cd vk-bot-learn
git remote add upstream https://github.com/ВАШ_ЛОГИН/vk-bot-learn.git
git fetch upstream
git switch -c feature/chill upstream/develop
git push -u origin feature/chill
```

И открывает PR из форка в ваш `develop`.

**Форк — это не ветка, а отдельная копия репозитория.**

### 1.4 «Закрепить ветку за человеком»

Git не умеет закреплять ветки. В GitHub для этого есть:

- **Branch protection** для `main` и `develop`:
  - запрет прямых пушей;
  - обязательный PR;
  - минимум 1 approval;
  - запрет force push.
- **CODEOWNERS** — автоматически назначает ревьюера на файлы:

```gitignore
# .github/CODEOWNERS
/app_tracker/bot/       @логин_A
/app_tracker/models.py  @логин_B
/app_users/             @логин_B
```

- **Assignees / Reviewers** в PR — это и есть закрепление задачи за человеком.

### 1.5 Первый push

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/vk-bot-learn.git
git push -u origin main develop
```

Сейчас `main` — старая база, `develop` — актуальная версия. Когда `develop` станет стабильным, влить его в `main`.

### 1.6 Ежедневный цикл

```bash
git switch develop
git pull --rebase origin develop

git switch feature/название
git rebase develop
```

Конфликты решаются в своей ветке через rebase, а не merge из `develop` в фичу.

## 2. Роли и границы файлов

| Разработчик A | Разработчик B |
|---|---|
| `app_tracker/bot/router.py` | `app_tracker/models.py` |
| `app_tracker/bot/onboarding.py` | `app_tracker/admin.py` |
| `app_tracker/bot/reporting.py` | `app_tracker/bot/storage.py` |
| `app_tracker/bot/screens.py` | `app_tracker/bot/vk.py` |
| `app_tracker/bot/texts.py` | `app_tracker/bot/helpers.py` |
| `app_tracker/bot/keyboards.py` | `app_users/` |
| `app_tracker/bot/states.py` | `config/` |
| Сценарии, тексты, клавиатуры | Модели, миграции, админка, веб, медиа, cron |

### Главные правила

1. **`models.py` и миграции меняет только B.**
2. A не делает `makemigrations`.
3. Если A нужна новая функция в `storage.py`, B добавляет её по согласованному имени.
4. Перед изменением модели B пишет в чат: «беру models.py, миграция X», делает, коммитит, пушит.
5. A перед продолжением делает `git pull --rebase`.

## 4. Детали по фичам

### 4.1 Модераторы

- Django-группа `Модераторы`.
- Права только на просмотр:
  - `view_participant`
  - `view_report`
  - `view_media`
  - `view_activity`
  - `view_goalperiod`
- Пользователям группы выставить `is_staff = True`, иначе админка недоступна.
- Не давать `change` и `delete`, если модераторы только проверяют данные.
- Создание группы — data-миграцией или вручную; для повторяемости лучше миграцией.

**Готово, когда:** модератор входит в `/admin/`, видит всех участников и отчёты, но не может их менять.

### 4.2 `photo_id` и `sex`

- `Participant.photo_id = CharField(max_length=100, blank=True)`.
- `Participant.sex = SmallIntegerField(choices=[(0, "—"), (1, "Ж"), (2, "М")], default=0)`.
- При `users.get` запрашивать `fields="photo_id,sex,photo_200"`.
- Для дашборда хранить `photo_url` из `photo_200`.
  `photos.getById` при каждом показе страницы — лишний запрос к ВК и зависимость веба от токена. Если нужен именно `photos.getById`, вызывать при обновлении профиля и кэшировать URL.
- Если `sex = 0` или фото скрыто — заглушка.

**Перед миграцией:** B предупреждает A, A делает `git pull --rebase`.

### 4.3 Chill

- Константа `CHILL_LIMIT = 3` в `app_tracker/bot/constants.py`.
- `Report.is_chill = BooleanField(default=False)`.
- Кнопка в меню: `[Отметиться] [Chill 3/3]`.
- Использовано за месяц:
  ```python
  Report.objects.filter(
      participant=participant,
      date__year=day.year,
      date__month=day.month,
      is_chill=True,
  ).count()
  ```
- «3/3» — остаток: `CHILL_LIMIT - used`.
- При нажатии: предупреждение «Chill можно 3 раза в месяц. Это 1-й. Продолжить?»
  Кнопки `[Передумал]` (зелёная) и `[Продолжить]` (красная).
- После лимита кнопку не показывать; на старую кнопку отвечать «Лимит исчерпан».
- Цвета ВК: `primary` — синий, `secondary` — серый, `positive` — зелёный,
  `negative` — красный. **Жёлтого и оранжевого в ВК нет.**

**Готово, когда:** кнопка показывает остаток, считает Chill за месяц, скрывается после 3-го, предупреждение работает.

### 4.4 «Изменить цели» и пауза

Самая сложная фича: текущая модель хранит только один набор целей на участника.

Нужна новая модель:

```python
GoalPeriod:
    participant FK
    month         # "2026-11"
    goal_1..3
    status        # active | paused
    unique(participant, month)
```

Почему:

- 29 ноября ставим цели на декабрь, ноябрьские продолжают работать;
- 1 декабря декабрьские становятся текущими;
- пауза — это `GoalPeriod(month=декабрь, status=paused)`.

Константы:

```python
ON_PERIOD_GOALS = 29
OFF_PERIOD_GOALS = 3    # включительно
PAUSE_LIMIT = 3         # за календарный год
```

Функции:

- `is_goals_window(day)` — `day >= 29 or day <= 3`;
- `target_goals_month(day)` — если `day >= 29`, следующий месяц, иначе текущий;
- кнопка «Изменить цели» видна только в окне;
- паузы считаются по `GoalPeriod` со статусом `paused` за текущий год;
- подпись `Остывать 3/3` — остаток;
- после использования паузы в текущем окне при следующем нажатии «Изменить цели»
  сразу идём к вводу целей, без двух кнопок;
- если пауз уже 3 — кнопку «Остывать» не показываем.

Старые `Participant.goal_1..3/goals_month` перенести в `GoalPeriod` data-миграцией.

**Это отдельная ветка `feature/goals-window`.**

**Готово, когда:** кнопка появляется 29–3, ведёт на две кнопки, пауза считается за год, цели ставятся на следующий месяц.

### 4.5 «Я перегорел»

- Кнопка в меню.
- Экран предупреждения: «Это удалит твои данные и завершит участие».
  Кнопки `[Передумал]` (зелёная) и `[Продолжить]` (красная).
- После подтверждения:
  - удалить `Participant`, `GoalPeriod`, `Report`, `Media`, `Activity`, `Profile`, `BotState`;
  - удалить файлы медиа с диска;
  - уведомить Влада через `OWNER_VK_ID`;
  - отправить деловое сообщение: «Данные удалены. Пожалуйста, покинь сообщество самостоятельно».
- **Бот не может гарантированно удалить человека из сообщества** токеном сообщества.
  Это делается вручную или отдельным методом с пользовательским токеном.
  Не обещать автоматическое исключение.

**Готово, когда:** подтверждение работает, данные и файлы удаляются, Влад получает уведомление.

### 4.6 Отметка с медиа

- Добавить `Report.note` (`TextField`) и модель `Media`.
- После третьего ответа «Да» — шаг `REPORT_MEDIA`:
  - фото или видео **40–60 секунд**;
  - если медиа нет — обязательное короткое примечание;
  - если медиа есть — примечание опционально.
- `Media`:
  ```python
  report FK (nullable)
  activity FK (nullable)
  kind photo/video
  file
  external_id
  duration
  created_at
  ```
  Ровно один владелец: либо report, либо activity.
- Фото скачивать. Видео — best-effort; если не скачалось, хранить `external_id`.
- Файлы в `MEDIA_ROOT/reports/<YYYY-MM>/<report_id>/`.
- Команда `cleanup_media` — удалять всё старше двух месяцев
  (текущий и прошлый месяц оставляем).
- «Отметиться» — красная (`negative`). «Отмена» — жёлтой в ВК нет,
  использовать `primary` (синий) или `secondary`.

**Готово, когда:** после отметки бот просит медиа/пояснение, сохраняет файл и текст, старые медиа удаляются по cron.

### 4.7 Активность

- Модель `Activity`:
  ```python
  participant FK
  kind: self_day | boost | meeting
  note
  created_at
  ```
- Меню `[Активность]`; оранжевого в ВК нет — использовать `positive` или `primary`.
- 4 кнопки: «Мой день», «Буст», «Встреча», «Отмена».
- После выбора — медиа/примечание по тем же правилам, что в отметке.
- Нужно решить: есть ли лимиты (например, «Мой день» раз в день),
  добавляют ли активности баллы.

**Готово, когда:** все 4 кнопки работают, активность сохраняется, медиа/пояснение пишутся.

### 4.8 Дашборд: фото и пол

- Аватар из `photo_200`/`photo_id`.
- Значок пола: ♀ / ♂ / «—».
- Если фото нет — инициалы.
- Показывать на `/` рядом с именем.

**Готово, когда:** на главной видно фото и значок пола, при отсутствии — аккуратная заглушка.

## 5. Правила работы

1. Никто не пушит напрямую в `develop` — только PR.
2. Одна фича — одна ветка:
   - `feature/chill-limit`
   - `feature/goals-window`
   - `feature/media-checkin`
   - `feature/activity`
   - `feature/burnout`
   - `feature/moderation`
   - `feature/profile-photo`
3. Перед началом дня:
   ```bash
   git switch develop
   git pull --rebase origin develop
   git switch feature/...
   git rebase develop
   ```
4. Миграции — только B.
5. PR — маленький, до 300–400 строк, с описанием «что сделано, как проверить».
6. Ревью — второй разработчик смотрит код и прогоняет сценарий вручную.
7. Конфликты — через `git rebase develop` в своей ветке.
8. Не редактировать применённые миграции. Только новая миграция.
9. `.env`, `db.sqlite3`, `bot.log` не коммитить.
10. После merge удалить ветку и обновить `develop`.

## 6. Открытые вопросы

Решить до кода:

1. **Chill:** день Chill закрывает «Отметиться» до завтра?
   Может ли Chill сочетаться с частично выполненными целями?
2. **Пауза:** 3 раза за календарный год. После первой паузы кнопка «Остывать»
   скрывается до следующего окна или навсегда? Если навсегда — лимит 3
   никогда не будет достигнут.
3. **Окно 29–3:** ставим цели на следующий месяц, текущий продолжает работать — подтверждаем?
4. **Активность:** лимиты на «Мой день»/«Буст»/«Встреча», дают ли они баллы?
5. **Медиа:** сколько файлов максимум? Видео именно 40–60 секунд или «до 60»?
   Если видео не скачалось — хранить ссылку ВК?
6. **Перегорел:** удалять и веб-аккаунт `User`, или только данные участника?
7. **Модераторы:** только просмотр или ещё возможность писать замечания?
